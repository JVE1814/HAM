## Findings considered and rejected

- Splitting recharts off the workspace bundle: the entry is 120 KB gzipped, assets cache for a year,
  and its main user is the landing dashboard.
- Double-submit on the customer page: the server already refuses the repeat (`platform/returns.ts`
  "awaited", `entry/customer.ts` 409).
- List metadata waterfall, three Stats calls for the Margin `currencyBar` widgets, the rack page's
  UTC "today", duplicate stylesheet links in built HTML: trivial impact.
- The SDK chain's 9 high advisories (undici, zod, joi via `@servicenow/sdk`): npm's only fix is an
  SDK downgrade. Wait for an SDK release.
- Dev-dependency major lag (TypeScript, vite, eslint): no EOL or incompatibility makes staying
  behind costly. Vitest is the exception, planned in 019 for its advisories.
- The `cn` dependency: it is the shadcn package, imported by 30 files.
- Stats aggregates with `^NQ` counting past an inventory tech's scope: rests on unconfirmed platform
  semantics and exposes counts only.
- Duplicate up/down device-event rows on an NMS resend: nothing reads them.
- `plan.md` §18's out-of-date testing promises: that section is kept as written, by its own note.
- Tech debt and structure: no change keeps needing N files in lockstep; churn on small entry files
  comes from repo-wide sweeps. `.audit/untangle/redesign.md` already covers the structural options.
- An AI (Now Assist) spike, plan Q68: the plan names no use case. It needs the owner to pick one
  before a plan can be written.
